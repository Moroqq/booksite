## 2. Как всё устроено сейчас

### Заказы и записи — без регистрации

Аккаунтов нет. После оформления покупатель получает письмо с **личной ссылкой** на свой заказ
(`/order/<ключ>`), по ней всегда видно состояние. Для семинаров то же самое (`/signup/<ключ>`).
Если письмо потерялось — страница **«Мой заказ»** (`/check`): поиск по номеру заказа и телефону,
обычной формой без JavaScript.

Почему не сделали вход: по 406-ФЗ авторизовать посетителей из России можно только через
российский номер телефона, Госуслуги, ЕБС или российскую систему вроде VK ID и Яндекс ID.
С 7 июля 2026 за нарушение штрафуют (ст. 13.55 КоАП: граждане 10–20 тыс., ИП 30–50 тыс.,
юрлица 500–700 тыс.). Telegram и вход по коду на почту в разрешённый список не входят.

**Код входа через VK ID и Яндекс ID написан, протестирован и лежит в проекте выключенным.**
Включится сам, как только в `.env.local` появятся ключи — но для их получения нужен статус
самозанятого или ИП (в VK Business ID есть категория «Физическое лицо» и «Самозанятый»).

### Письма

Ящик `noreply@zvukterap.ru` на почтовом хостинге reg.ru, отправка через `mail.hosting.reg.ru:465`.
Проверка доставляемости — **10 из 10**: подпись DKIM и SPF проходят, в чёрных списках нет.

Уходят автоматически: подтверждение заказа с реквизитами и ссылкой, смена статуса заказа,
подтверждение заявки на семинар, подтверждение или отказ участия, уведомления вам на
`info@zvukterap.ru` о каждом новом заказе и заявке.

Напоминания раз в час проверяет системный планировщик (`booksite-reminders.timer`):
об оплате, если заказ висит неоплаченным больше суток, и о семинаре за день до начала.
Каждое уходит один раз.

Проверить почту: `node scripts/check-mail.mjs` (вход) или `node scripts/check-mail.mjs адрес@почта`
(пробное письмо).

### Скорость

Вступительная анимация — видео 0,5 МБ для телефонов и 0,8 МБ для компьютеров вместо прежних
116 картинок на 55 МБ. Картинки отдаются в WebP и хранятся 30 дней. **AVIF отключён намеренно:**
на сервере одно ядро, и кодирование в AVIF занимает ~5,7 с против ~0,8 с у WebP при том же весе.

## 3. Как выкладывать изменения

```
ssh root@193.233.48.36
cd /var/www/booksite
git pull --ff-only origin main
npm install
npm run build
pm2 restart booksite --update-env
node scripts/warm-images.mjs https://zvukterap.ru
```

**Не используйте `npm install --omit=dev`** — сборке Next нужны инструменты разработки,
иначе сборка падает и сайт отдаёт 502.

**Меняя картинку или видео, сохраняйте файл под новым именем** (`intro-v2.webm`,
`arnold-4.jpg`). Иначе посетители месяц будут видеть старую версию из кеша.
Если всё же заменили под тем же именем — `rm -rf .next/cache/images` и следом прогрев.

**Прогрев** в последней строке заранее готовит все картинки, иначе первый посетитель
после выкладки ждёт, пока сервер их обработает.
