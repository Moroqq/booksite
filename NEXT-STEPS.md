## 1. Что нужно сделать вам (без этого вход не заработает)

Код входа через VK ID и Яндекс ID написан и лежит на сервере, но **выключен**, пока не заданы
ключи. Сейчас сайт работает по-старому: заказ книги и запись на семинар оформляются без входа.
Как только ключи появятся, вход автоматически станет обязательным.

### VK ID

1. Откройте https://id.vk.com/about/business и создайте приложение.
2. Платформа — **веб-сайт**, адрес сайта: `https://zvukterap.ru`
3. Доверенный redirect URL (адрес возврата): `https://zvukterap.ru/api/auth/vk/callback`
4. Запросите доступ к **почте** и **телефону** — из них подставляются поля заказа.
5. Скопируйте **ID приложения** (client_id). Секрет для этого способа входа не нужен.

### Яндекс ID

1. Откройте https://oauth.yandex.ru и создайте приложение.
2. Платформа — **веб-сервисы**, Redirect URI: `https://zvukterap.ru/api/auth/yandex/callback`
3. Права доступа: адрес электронной почты, имя и фамилия, номер телефона.
4. Скопируйте **ClientID** и **Client secret**.

### Куда вписать ключи

Зайдите на сервер и выполните одну команду, подставив свои значения:

```
ssh root@193.233.48.36
cd /var/www/booksite && printf 'VK_CLIENT_ID=ВАШ_ID\nYANDEX_CLIENT_ID=ВАШ_ID\nYANDEX_CLIENT_SECRET=ВАШ_СЕКРЕТ\n' >> .env.local
pm2 restart booksite --update-env
```

Пересобирать проект не нужно — достаточно перезапуска. `SITE_ORIGIN=https://zvukterap.ru`
на сервере уже прописан.

## 2. Что уже сделано

**Вход и личный кабинет** (коммит `5b5961f`)
- Вход через VK ID (протокол OAuth 2.1 с PKCE) и Яндекс ID. Пароли не используются.
- `/login` — страница входа, `/account` — личный кабинет: заказы книги и записи на семинары
  с их состоянием. Видно с любого устройства.
- Заказ книги (`/book/order`) и запись на семинар просят войти. Имя, почта и телефон
  подставляются из аккаунта.
- Запись на семинары сделана с нуля: форма, хранение заявок, номера вида `SM-2026-0001`.
- Админка: раздел «Записи на семинары» — подтвердить, отклонить с причиной, отменить.
  Причина отказа видна человеку в кабинете.

**Скорость и мобильная версия** (этот коммит)
- Вступительная анимация была 116 картинок PNG общим весом 55 МБ — браузер тянул их все
  до начала показа. Теперь это одно видео: 0,8 МБ (WebM) или 1 МБ (MP4) плюс мгновенная
  заставка. Телефонам отдаётся уменьшенная версия 640 px (~0,5 МБ), компьютерам — полная
  1052 px. Папка `public/frames` удалена, кадры остались в истории git. Браузер держит
  видео в кеше месяц — если будете менять анимацию, сохраните файлы под новым именем
  (`intro-v2.webm`), иначе посетители месяц будут видеть старую версию.
- Мобильное меню переделано: выезжает справа поверх затемнённой страницы, закрывается
  крестиком, касанием мимо и клавишей Esc, список прокручивается на маленьких экранах,
  кнопка «Купить книгу» закреплена внизу и занимает всю ширину.
- Починен фон шапки при прокрутке — он не отображался (см. пункт 3).

## 3. Что осталось незакрытым

**Прозрачность цветов не работает по всему сайту.** В проекте 105 классов вида
`bg-[var(--gold)]/15`, `text-[var(--ink-soft)]/60` в 35 файлах. Tailwind не умеет накладывать
прозрачность на цвет из CSS-переменной и **молча выбрасывает** такие классы — они не попадают
в стили вообще. Из-за этого пропадали фон шапки, подложки плашек и разделители. В шапке и меню
это уже исправлено явными цветами; остальные 35 файлов нужно пройти отдельной задачей.

**Почта не подключена.** Письма о заказах и семинарах никуда не уходят — сервиса отправки нет.
Поэтому состояние заказа человек видит только в личном кабинете, и это одна из причин,
по которой вход сделан обязательным.

**Нерабочий адрес почты.** Внизу страницы семинаров кнопка «Написать нам» ведёт на
`info@zvukoterapia.ru` — это чужой домен, письма туда не дойдут. Нужен реальный адрес.

## 4. Как выкладывать изменения на сайт

```
ssh root@193.233.48.36
cd /var/www/booksite
git pull --ff-only origin main
npm run build
rm -rf .next/cache/images
pm2 restart booksite --update-env
```

Строка `rm -rf .next/cache/images` обязательна, если менялись картинки в `public/images/`
под теми же именами: без неё сайт продолжит отдавать старые изображения из кеша,
хотя файлы на диске уже новые.

## 5. Почта: что осталось сделать (добавлено 18 августа)

Отправка писем написана и проверена — сайт умеет писать людям. Пока настройки не заданы,
письма просто не уходят, и сайт работает как обычно.

**Какие письма уже готовы:**
- покупателю — подтверждение заказа с суммой и реквизитами перевода;
- покупателю — «оплата получена», «заказ отправлен», «оплата не найдена» с вашей причиной;
- участнику — подтверждение заявки на семинар, подтверждение участия, отказ с причиной;
- вам — уведомление о каждом новом заказе и каждой новой заявке.

**Шаг 1. Завести ящик.** В reg.ru: Почтовые сервисы → Почтовые ящики → создать на домене
`zvukterap.ru`, например `noreply@`. Услуга платная, от 99 ₽ в месяц за домен (не за ящик).

**Шаг 2. Прописать записи в Cloudflare.** Домен зарегистрирован в reg.ru, но DNS ведёт
Cloudflare — значит записи добавляются там, иначе почта не заработает. Нужны MX (их выдаст
reg.ru), SPF и DKIM. SPF для reg.ru:

```
v=spf1 ip4:31.31.198.150 a mx include:_spf.hosting.reg.ru ~all
```

Без DKIM письма про заказы с большой вероятностью попадут в спам — не пропускайте этот шаг.

**Шаг 3. Вписать настройки на сервер:**

```
ssh root@193.233.48.36
cd /var/www/booksite && printf 'SMTP_HOST=ХОСТ_ОТ_REGRU\nSMTP_PORT=465\nSMTP_USER=noreply@zvukterap.ru\nSMTP_PASSWORD=ПАРОЛЬ_ЯЩИКА\nMAIL_FROM=noreply@zvukterap.ru\nMAIL_TO_ADMIN=ВАШ_АДРЕС_ДЛЯ_УВЕДОМЛЕНИЙ\n' >> .env.local
pm2 restart booksite --update-env
```

Пересборка не нужна. После этого оформите тестовый заказ на себя и проверьте, что письмо
пришло и не попало в спам.

**Важно про закон.** Почта решает уведомления, но НЕ делает законным вход по коду на email:
ограничение 406-ФЗ касается того, чем подтверждается личность посетителя, а не того, с какого
адреса сайт шлёт письма. Разрешённые способы входа — российский номер телефона, Госуслуги,
ЕБС и российские системы вроде VK ID и Яндекс ID.
